# 晚宴賓果

約 100 人導生晚宴使用的手機賓果，含玩家、主持人與投影畫面，以及開獎時的號碼滾動動畫。Oracle Cloud ARM VPS 部署範本已備妥，待確認主機環境後再實際部署。

## 本機立即試玩

需要 Python 3.9 以上，無須 npm、pip 或外部服務。正式容器使用 Python 3.13。

```sh
python3 manage.py demo
python3 app.py --db data/demo.sqlite3
```

| 畫面 | 網址 |
| --- | --- |
| 玩家 | http://127.0.0.1:8000/ |
| 主持人 | http://127.0.0.1:8000/host |
| 投影 | http://127.0.0.1:8000/display |

示範主持人密碼：`demo-host-2026!`。示範資料庫固定為 `data/demo.sqlite3`，預先產生 150 組碼、開放領卡，僅允許 loopback 啟動，不能當正式活動部署。

登入後台 → 展開「查看領卡名單與代碼」→ 複製其中一組到玩家頁 → 輸入稱呼領卡 → 後台抽號。可在另一分頁看投影同步。重新整理後保留原卡；如果換裝置或 cookie 遺失，可用原碼恢復。

`demo` 再次執行會保護既有資料而拒絕覆寫，之後直接啟動即可。不要把正式資料庫刪掉或換成示範資料。

## 同一個 Wi-Fi 的手機測試

內網用來測試手機操作；正式活動仍部署到 Oracle Cloud ARM VPS。這裡使用獨立的 `data/lan-test.sqlite3`，測試領卡、抽號與得獎紀錄留在該檔案。

先在專案資料夾初始化一次，依提示自行設定至少 12 字元的測試主持人密碼：

```sh
python3 manage.py --db data/lan-test.sqlite3 init --title '導生晚宴・內網測試' --tickets 150
```

之後每次測試只需啟動伺服器：

```sh
BINGO_PUBLIC_URL= python3 app.py --db data/lan-test.sqlite3 --host 0.0.0.0 --port 8000
```

`BINGO_PUBLIC_URL=` 讓這次測試以 HTTP 運作。`data/demo.sqlite3` 限制在本機使用，手機測試請使用上述獨立資料庫。

1. 主機與手機連上可互通的同一個 Wi-Fi／區網。Mac 可到「系統設定 → Wi-Fi → 已連線網路的詳細資訊 → TCP/IP」查看 IPv4 位址，或在終端執行 `ipconfig getifaddr en0`；若 en0 沒有位址，以網路設定顯示的為準。
2. 假設 Mac 的區網 IP 是 `192.168.1.100`，手機以 Safari／Chrome 開啟 `http://192.168.1.100:8000/`。這是示例 IP，請換成自己的。`0.0.0.0` 是監聽設定，玩家應開啟實際區網 IP。
3. 主持人使用 `http://192.168.1.100:8000/host` 登入，按「開放領卡」；從碼表拿一組碼在手機領卡，或在後台列印專屬 QR 碼。列印與開啟投影頁都使用這個區網 IP，QR 才會指向手機可連到的網址。
4. 電腦開 `http://192.168.1.100:8000/display` 看投影，後台抽號，確認手機同步。再測試重新整理、關頁重開及暫時斷線後恢復。

主機保持供電、不要休眠，執行伺服器的終端須保持開啟；按 Ctrl+C 結束測試，之後用相同啟動指令恢復資料。IP 或連接埠改變時，手機要改用新網址登入／以原碼恢復，並重新產生 QR 券。

如果手機連不上，先確認網址含 `http://` 與 `:8000`、Mac 防火牆允許 Python 傳入連線，以及 Wi-Fi 沒有阻擋裝置互相存取的訪客網路隔離。可先在主機用相同區網網址開 `/healthz`，應顯示 `{"ok": true}`，再用手機測試；主機成功、手機失敗時，接著檢查防火牆及 Wi-Fi 互通設定。Mac 防火牆操作參考 [Apple 支援](https://support.apple.com/zh-tw/guide/mac-help/mh34041/mac)。

這個 HTTP 區網測試不經 Oracle VPS；正式部署的 HTTPS 步驟見 [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)。

## 功能與規則

- 5×5，1～49 中隨機 24 個不重複號碼，中央免費格。橫、直、兩條對角線，共 12 條可能連線。
- 主持人每抽一號，伺服器檢查所有卡片。以第一次達成連線的**開獎回合**決定資格；沒有搶按中獎按鈕，也不會採信玩家勾選。
- 每局最多 10 位，每位玩家每局限一次。某回合超出剩餘名額時，用作業系統亂數打亂該回合候選人，再取剩餘名額；候選人、完整隨機順序、入選結果與時間，在同一 SQLite 交易保存。
- 額滿或 49 號全數抽完即結束。未滿 10 人時，號碼抽完仍可能少於 10 位得主。
- 初次開獎自動關閉新領卡，不接受中途參賽；恢復既有卡不受影響。
- 一碼對應一個玩家；重複送出只恢復相同身分，不新增卡。原碼也有恢復權限，應保留紙券、不要分享。
- 同一瀏覽器有有效玩家登入時，不能用另一張券再領卡。**工作人員仍須每位實際來賓只發一張券**，不蒐集實名證件，系統無法識別同一人拿兩張不同券使用不同裝置。
- 下一局保留歷史資料，替所有已登記玩家自動換發新卡，清空本局勾選並重開 10 個名額。原領卡碼與身分沿用，新局領卡預設關閉。此處「每人一次」以每局計算。
- 手動勾選存於伺服器；離線時暫存在該裝置 localStorage，重連後補存。未完成初次領卡不能離線新領卡。

## 設計與維護

- 開獎時播放約 2.4 秒的號碼滾動與減速，再以金色光圈定格；本回合開獎紀錄與得獎名單一起揭曉。主持人動畫期間暫停下一次抽號，玩家頁也有輕量的號碼效果。
- 動畫只呈現伺服器已保存的結果，播放中途重新整理、斷線補查、切換局次或切回背景，都可恢復已保存的進度。系統開啟「減少動態效果」時直接顯示結果。動畫使用伺服器回傳的時間縮短延遲，不受手機時鐘誤差影響；裝置效能與網路仍可能造成揭曉時間差。
- 動畫在各瀏覽器本地播放，不新增抽號／輪詢請求，不載入外部動畫套件。更新後重新啟動 Python 服務，並重新整理玩家、後台與投影頁，以載入新版本。
- Python 標準函式庫 HTTP 服務、SQLite WAL、單程序多執行緒、SSE 即時通知與 15 秒補查。
- 每張卡、開獎、連線回合、領獎時間、主持人操作與登入工作階段都持久保存。抽號帶預期局次／回合，重複點擊、延遲重送或兩個主持人分頁不會連抽兩號。
- 主持人密碼採 PBKDF2-SHA256、cookie 使用 HttpOnly/SameSite，正式 HTTPS 加 Secure；寫入需 CSRF token，同源檢查，登入有速率限制。
- 專屬 QR 碼放在網址 fragment，頁面讀取後即移除；不會寫入 HTTP 路徑或參照網址。所有靜態資產本地提供，現場無須連字型或 CDN。
- `/display` 為公開只讀投影頁；會顯示玩家自行填寫的得獎稱呼及卡號，請避免填敏感資料。主持人碼表、玩家卡片與完整抽選紀錄需登入才可讀取。
- 單一應用程序／副本；請勿啟動多個 server 程序共用此 DB，因即時通知使用程序內 Condition。未設計為多台分散式部署。

## 驗證

```sh
python3 -B -m unittest discover -s tests -v
python3 -B scripts/load_test.py --players 150 --rounds 5
```

測試只使用獨立暫存資料庫，不會動正式活動。完整測試範圍、量測及仍需實機驗收項目見 [docs/TESTING.md](docs/TESTING.md)。執行環境須允許綁定本機 TCP 暫用埠。

前端動畫另有狀態流程測試；若已安裝 Node.js，可使用內建測試工具執行，不需要 npm 套件。執行賓果伺服器仍只需要 Python：

```sh
node --test tests/draw-animation.test.mjs
```
